# IONIC format — version 1

This file is the exact byte layout for IONIC `format_version = 1`. It is the contract:
the reader and the writer must match it byte for byte.

- `format_version` (header byte 9) is `1`. A reader uses this number to pick the spec.
- Status: pre-release (package `0.1.0`). The bytes may still change before the freeze.
- A breaking change (new codec id, new dtype value, new section layout) creates a new
  file `spec/v2.md` and sets `format_version = 2`. The reader fail-hards on unknown
  codec or dtype values; encountering one means the file was written by a newer version
  and the reader must upgrade.

All integers are little-endian. The file is seekable; the header is written last.

## Design rules

- Source-independent: the format stores items, arrays, summaries, metadata, and
  offsets into its own file. It knows nothing about where the data came from.
- Metadata is keyed by PSI accession. Structural attributes with no PSI term use
  Ionic's reserved attribute namespace. The accession is the authority, never the
  human name.
- Offsets and lengths in the header are authoritative. Physical order is fixed but a
  reader must trust the header, not adjacency.

## Section map

| Letter | Role                                                 | Shape                                  |
| ------ | ---------------------------------------------------- | -------------------------------------- |
| header | file header                                          | fixed 1024 bytes                       |
| —      | spectrum array blocks (`packed_spectra`)             | block container, directory at tail     |
| —      | chromatogram array blocks (`packed_chroms`)          | block container, directory at tail     |
| A0     | spectrum fast-filter summary (`spec_summary`)        | fixed 128-byte record per spectrum     |
| A1     | spectrum m/z-window bounds — m/z bounds per window | 24-byte row per window   |
| A2     | spectrum array index (`spec_entries`)                | fixed 16-byte record per spectrum      |
| A3     | spectrum array refs (`spec_arrayrefs`)               | fixed 32-byte record per array         |
| B0     | chromatogram fast-filter summary (`chrom_summary`)   | fixed 128-byte record per chromatogram |
| B1     | chromatogram segment bounds                          | 24-byte row per searchable segment     |
| B2     | chromatogram array index (`chrom_entries`)           | fixed 16-byte record per chromatogram  |
| B3     | chromatogram array refs (`chrom_arrayrefs`)          | fixed 32-byte record per array         |
| C      | spectrum metadata (`spec_meta`)                      | grouped, directory at tail             |
| D      | chromatogram metadata (`chrom_meta`)                 | grouped, directory at tail             |
| E      | global metadata (`global_meta`)                      | one monolithic compressed section      |

A0+A1 are the "maps" group (summary + m/z bounds); A2+A3 are the "block access" group (index + refs).

Physical order: header, packed_spectra, packed_chroms, A0, A1, A2, A3, B0, B1, B2, B3,
C, D, E, trailer. Every section starts on an 8-byte boundary. A0/A2/A3/B0/B2/B3 are
never compressed; A1/B1 are compressed with the file codec when compression is enabled.

## A0 — spectrum fast-filter summary (128 bytes)

A0 is a rebuildable acceleration cache: every used field is derived from the spectrum's
metadata in C under its PSI accession. A0 can be rebuilt from C. The header carries a
CRC32 for A0 at offset 968.

| Offset | Size | Field             | Type / sentinel                        | State |
| ------ | ---- | ----------------- | -------------------------------------- | ----- |
| 0      | 8    | rt                | f64, raw value in the unit at byte 54  | used  |
| 8      | 8    | base_peak_mz      | f64                                    | used  |
| 16     | 8    | selected_ion_mz   | f64                                    | used  |
| 24     | 8    | base_peak_int     | f64                                    | used  |
| 32     | 8    | total_ion_current | f64                                    | used  |
| 40     | 1    | ms_level          | u8                                     | used  |
| 41     | 1    | polarity          | u8 (0 unknown, 1 positive, 2 negative) | used  |
| 42     | 4    | position_x        | u32, 0 = unknown                       | used  |
| 46     | 4    | position_y        | u32, 0 = unknown                       | used  |
| 50     | 4    | position_z        | u32, 0 = unknown                       | used  |
| 54     | 1    | rt_unit           | u8 (0 unknown, 1 second, 2 minute, 3 millisecond) | used |
| 55     | 73   | tail              | zero                                   | free  |

A0 and B0 stay exactly 128 bytes forever. The free tail may gain optional fields. Each
tail slot, once assigned an offset, keeps that offset, type, sentinel, unit, and
canonical metadata accession forever and is never reused for another meaning. Readers
ignore slots they do not know; writers zero any tail bytes they do not set.

## A1 — spectrum m/z-window bounds (24 bytes per window)

A1 is the m/z map: it accelerates axis-aligned range queries in spectra. The header
points to it (off/len at 48/56) and carries a CRC32 for A1 at offset 972. A1 is a list
of 24-byte rows, sorted by `array_ref_index` ascending:

| Offset | Size | Field                                               |
| ------ | ---- | --------------------------------------------------- |
| 0      | 8    | array_ref_index (which A3 ref this row describes)   |
| 8      | 8    | low (f64) — window lower m/z: smallest m/z stored in that window     |
| 16     | 8    | high (f64) — window higher m/z: largest m/z stored in that window    |

Each window is one m/z slice of one spectrum, so `low` and `high` are that window's
lower and upper m/z. They are the **true min and max of the values as stored** in the
block; for an array stored as f32 they are the min and max of the decoded f32 values, so
the bounds stay exact to what a reader retrieves. One row exists per window, not per
array. "Searchable" means an axis a reader filters on — m/z (MS:1000514) by default, but
also drift time, raw ion mobility, or any other array accession that increases across the
array, where the window runs along that axis.

**A1 is required for m/z range reads. There is no full-array fallback.** A missing,
CRC-failed, or malformed A1 is an error. The writer guarantees A1 exists by rejecting
any spectrum whose m/z array is not sorted ascending. A1 is compressed with the file
codec when compression is on.

To read values in `[query_low, query_high]`: keep a window if
`window_low <= query_high` and `window_high >= query_low`. Decode only the kept windows
and cut each to range.

## A2 — spectrum array index (16 bytes per spectrum)

A2 maps each spectrum to its array refs in A3. The header carries a CRC32 for A2 at
offset 976.

| Offset | Size | Field                           |
| ------ | ---- | ------------------------------- |
| 0      | 8    | first array ref index (into A3) |
| 8      | 8    | array ref count                 |

## A3 — spectrum array refs (32 bytes per array)

A3 holds one record per logical array segment. The header carries a CRC32 for A3 at
offset 980.

| Offset | Size | Field                                                                           |
| ------ | ---- | ------------------------------------------------------------------------------- |
| 0      | 8    | element offset (inside the block)                                               |
| 8      | 8    | element count                                                                   |
| 16     | 4    | block id (into the container directory)                                         |
| 20     | 4    | array accession                                                                 |
| 24     | 1    | dtype (see codes)                                                               |
| 25     | 1    | array filter (PackingId, see codes)                                             |
| 26     | 4    | encoded length (0 = fixed-width; >0 = variable-length byte count)               |
| 30     | 1    | continues_previous_segment (0 = new array, 1 = next segment of the array above) |
| 31     | 1    | reserved, zero                                                                  |

Many refs may point at the same block id and element offset; identical arrays may be
shared. The reader does not care whether arrays are shared.

One logical array may be stored as several refs in a row: the first has
`continues_previous_segment = 0`, each following segment has `continues_previous_segment = 1`.
To rebuild the whole array, read the segments in order and join them. A leading `1`, a
value above `1`, or a segment whose dtype or filter differs from the first is an error.
All segments of one array share the same accession, dtype, and filter.

## B0 — chromatogram fast-filter summary (128 bytes)

B0 is the chromatogram equivalent of A0 — a rebuildable acceleration cache derived from
D. The header carries a CRC32 for B0 at offset 984.

| Offset | Size | Field                | Type / sentinel | State |
| ------ | ---- | -------------------- | --------------- | ----- |
| 0      | 8    | lowest_mz            | f64             | used  |
| 8      | 8    | highest_mz           | f64             | used  |
| 16     | 8    | lowest_wavelength    | f64             | used  |
| 24     | 8    | highest_wavelength   | f64             | used  |
| 32     | 8    | lowest_ion_mobility  | f64             | used  |
| 40     | 8    | highest_ion_mobility | f64             | used  |
| 48     | 1    | polarity             | u8              | used  |
| 49     | 79   | tail                 | zero            | free  |

Proposed future fields, not yet written and not yet locked to an offset:
`precursor_mz`, `product_mz` (both f64, NaN = unknown). They become `used` only when
the writer fills them and this table assigns them an offset.

B0/B1/B2/B3: chromatogram equivalents of A0/A1/A2/A3 — section bodies pending revision.

## Array containers (packed_spectra, packed_chroms)

Layout: `[block][block]…[block][block directory]`. Blocks are grouped by element
stride (1, 2, 4, 8 bytes); a block fills up to the target block size, then seals. An
array larger than the target gets its own dedicated block. Each block is compressed
independently when compression is on.

A spectrum's m/z and intensity arrays are cut into ordered **m/z windows**: the m/z axis is
split into fixed-width windows, and each window's slice becomes one A3 ref (the first has
`continues_previous_segment = 0`, each later window `1`). Windows over the same m/z range are
routed to shared blocks across spectra, so a reader that wants one m/z range opens only the
blocks for the windows it overlaps. The reader never needs the window width: it joins whatever
windows it finds and prunes by range, because A1 carries the m/z bounds of every window. The
writer always records its target window width at header offset 24 as a u32 in m/z units; when
no width is given it records the default (50), so the field always shows the real target.

Block directory entry (32 bytes), one per block:

| Offset | Size | Field                                        |
| ------ | ---- | -------------------------------------------- |
| 0      | 8    | payload offset (relative to container start) |
| 8      | 8    | payload size                                 |
| 16     | 8    | uncompressed length                          |
| 24     | 4    | crc32 of the stored payload                  |
| 28     | 4    | reserved, zero                               |

Each entry carries its own payload crc32, but the entry's offset and size are not
covered by it. The whole directory is therefore protected by one crc32 over all its
bytes, stored in the header (992 for spectra, 996 for chromatograms). A reader checks
this before it trusts any offset, so a corrupted offset cannot silently resolve to a
different valid block. An empty container has a zero-length directory and a crc32 of `0`.

## C / D — grouped metadata

Layout: `[group payload]…[group payload][group directory]`. Items are split into
fixed groups of `metadata group size` (8192) items. Each group is serialized, then
compressed independently when compression is on. A group's value pools are local: no
pool crosses a group boundary. **Metadata node IDs are also group-local**: each group
has its own node-ID space, with the list root at id `1` and item nodes starting at `2`.

Group directory entry (32 bytes), one per group:

| Offset | Size | Field                                      |
| ------ | ---- | ------------------------------------------ |
| 0      | 8    | payload offset (relative to section start) |
| 8      | 8    | payload size                               |
| 16     | 8    | uncompressed size                          |
| 24     | 4    | crc32 of the stored payload                |
| 28     | 4    | reserved, zero                             |

Decompressed group body. First a 12-byte header:

| Offset | Size | Field                           |
| ------ | ---- | ------------------------------- |
| 0      | 4    | meta_count (rows in this group) |
| 4      | 4    | numeric_count                   |
| 8      | 4    | string_count                    |

Then column arrays in this order (let `n = meta_count`, `g = items in this group`):

| Column                           | Type | Length                | Meaning                                                                          |
| -------------------------------- | ---- | --------------------- | -------------------------------------------------------------------------------- |
| `CI` local index offsets         | u32  | g + 1                 | `CI[i]`..`CI[i+1]` is the row slice for item `i`                                 |
| `MOI` ids                        | u32  | n                     | owner node id — which element owns this row                                      |
| `MPI` parent ids                 | u32  | n                     | parent node id — used with `MOI` to rebuild the element tree                     |
| `MTI` tag ids                    | u8   | n                     | tag id — which kind of element the row sits in (spectrum, scan, precursor, …)    |
| `MRI` CV ref codes               | u8   | n                     | CV vocabulary: `0` MS, `1` UO, `2` NCIT, `3` PEFF, `4` ATTR, `5` IMS, `255` none |
| `MAN` CV accession numbers       | u32  | n                     | numeric tail of the CV term (e.g. `1000285` for `MS:1000285`)                    |
| `MURI` unit CV ref codes         | u8   | n                     | CV vocabulary for the unit, same codes as `MRI`                                  |
| `MUAN` unit CV accession numbers | u32  | n                     | numeric tail of the unit CV term                                                 |
| `VK` value kinds                 | u8   | n                     | `0` numeric, `1` string, `2` empty                                               |
| `VI` value indices               | u32  | n                     | index into the pool selected by `VK`                                             |
| `VN` numeric values              | f64  | numeric_count         | pool of all f64 values; a numeric row reads `VN[VI]`                             |
| `VOFF` string offsets            | u32  | string_count          | byte start of each string in `VS`                                                |
| `VLEN` string lengths            | u32  | string_count          | byte length of each string in `VS`                                               |
| `VS` string bytes                | u8   | sum of string lengths | concatenated UTF-8 bytes; a string row reads `VS[VOFF[VI] : VOFF[VI]+VLEN[VI]]`  |

The term name (e.g. "total ion current") is never stored. A reader gets it from the
vocabulary at runtime using `MRI` and `MAN`. The `ATTR` vocabulary (ref code `4`) is
IONIC's own — it covers structural attributes with no PSI term (id, ref, index, count).
Its exact accession numbers are defined in `attr_meta.rs`.

## E — global metadata (monolithic)

One compressed section. It does not scale with item count, so it is not grouped. It
starts with a 32-byte counts header, then the same column arrays as a group body
(but for the whole section, with `index offsets` of length `items + 1`).

Counts header (32 bytes): nine u16 values in this order — file descriptions, ref
param groups, samples, instrument configs, software, data processing, acquisition
settings, cvs, runs — then 14 reserved zero bytes.

## Codes

Compression codec (header byte 11): `0` none, `1` zstd. An unknown codec id is a
breaking change — the reader fail-hards and requires a new `format_version`.

dtype (A2/B2 byte 24): `1` f64, `2` f32, `3` f16, `4` i16, `5` i32, `6` i64. An
unknown dtype value is a breaking change — the reader fail-hards and requires a new
`format_version`.

Array filter / PackingId (header byte 13, A2/B2 byte 25): `0` raw, `1` byte shuffle,
`2` delta shuffle.

## Integrity and validation

- The file starts with the signature `IONIC\0\0\0` and ends with the trailer
  `\0\0\0CINOI`.
- The header crc32 at offset 1020 covers header bytes 0..1020.
- All 14 section checksums are grouped at the header tail (968..1020): A0 at 968, A1
  at 972, A2 at 976, A3 at 980, B0 at 984, B1 at 988, B2 at 992, B3 at 996, spectrum
  block directory at 1000, chromatogram block directory at 1004, C at 1008, D at 1012,
  E at 1016.
- C, D, E each have a crc32 in the header over their whole section.
- Every block and every group carries its own crc32.
- Each block container directory carries one crc32 over all its bytes, stored in the
  header (1000 for spectra, 1004 for chromatograms). The reader checks it on open, before
  it trusts any block offset.
- A3 and B3 each carry a crc32 in the header (980 and 996). A3 and B3 are required
  for range reads; a failed CRC is an error, not a fallback.
- `total file size` equals the real file length.
- Sections do not overlap, are 8-byte aligned, and sit after the header.
- Reserved bytes at header 14..16 and 432..968 are checked zero on parse; a non-zero
  byte is an error.

Validation modes:

- Open: cheap directory checks only — directory bounds, each payload ends strictly
  before its directory, `sum(group uncompressed size)` equals the header total, and each
  block container directory matches its header crc32. No decompression.
- Random access: decode and checksum only the target group and the target item's
  blocks.
- Full read / strict: decode all groups and assert the full row, numeric, and string
  totals against the header.

## v1 limits

- Header item counts (spectra, chromatograms): u64.
- Metadata node ids are group-local: each 8192-item group restarts its node ids from a
  fixed base, so the u32 node-id space never accumulates across the file. Item count is
  bounded only by the u64 header counts, not by the node-id width.
- Rows, numeric, string counts per section: u32.
- Global counts: u16 (max 65535 each).
- String pool offsets: u32 (max 4 GiB per section).

## Extensibility (the only allowed growth)

Version 1 grows in exactly one way: **A0/B0 tail fields**. The reserved tail of A0 and
B0 may gain optional fields. Rules:

- A0 and B0 stay exactly 128 bytes forever.
- Each tail slot, once assigned an offset, keeps that offset, type, sentinel, unit,
  and canonical metadata accession forever, and is never reused for another meaning.
- A slot is used, reserved, or free (zero).
- Readers ignore slots they do not know. Writers zero any tail bytes they do not set.

The header reserved area at 448..992 stays checked-for-zero and is off-limits. Anything
there, or any change to a fixed layout above, is a real format change (a new
`format_version` and a new `spec/vN.md`).
